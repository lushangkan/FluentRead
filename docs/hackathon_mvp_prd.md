# FluentRead · MVP PRD

## 1. Project overview（项目概览）

### 1.1 产品定位

**FluentRead** 是一款基于 RSS 的英文阅读 App，面向母语为中文、正在学习英语的用户。

它从用户订阅的 RSS 源抓取英文文章，根据用户的词汇水平对文章进行「可读化重写」，让用户在手机上像刷新闻一样刷「难度合适的英文内容」。

### 1.2 核心目标（MVP）

在 MVP 中实现一条完整的 **Happy Path**：

1. 用户使用 **邮箱验证码登录**。
2. 首次登录时完成一次 **CEFR 词汇水平测试**（A1–C2），得到基础词表。
3. 用户订阅或使用内置 RSS 源（BBC / Hacker News），看到文章列表。
4. 用户点击文章：
    - 后端根据用户词表生成「可读化简化版」英文；
    - 前端展示简化版，支持一键切换原文。
5. 阅读过程中：
    - 用户点击单词查看 **英英释义**，可切换查看 **中文释义**；
    - 可在释义卡片中将该词标记为「认识 / 不认识」，更新个人词表。

**MVP 成功标准（定性）：**

- 评委可以在 Android App 上：
    - 登录 → 做测试 → 看到 News feed → 打开文章 → 看到简化版本 → 点击单词查释义并标记。
- 即使翻译处理较慢（1–3 分钟），流程依然可用、有反馈。

### 1.3 范围（Scope）

**本阶段包含：**

- Android 端（Flutter）App：
    - 邮箱验证码登录。
    - 首次 CEFR 词汇测试。
    - RSS 源订阅管理。
    - 文章列表展示。
    - 文章正文：简化版 / 原文切换。
    - 单词点击释义 & 标记 known/unknown。
- 后端（FastAPI + SQLAlchemy + Supabase Postgres）：
    - 用户 & Auth 对接 Supabase。
    - RSS 抓取与文章入库。
    - 词表基础数据与用户 patch。
    - 基于词表的文章「简化版」生成（LLM）。
    - 单词释义生成（LLM）。
- AI：
    - 使用 LLM 进行段落简化 & 单词释义（英英 + 中文）。

**本阶段不包含（Non-goals）：**

- iOS 客户端。
- Web/PWA 版本（可作为后续阶段目标）。
- 用户自定义上传文章 / 粘贴文本。
- 阅读统计、战报、打卡、勋章等激励系统。
- 完整背单词系统（记忆曲线、复习计划等）。
- CEFR 等级手动修改、重新测试入口。
- 多词/句子级选区释义与局部重写 patch。
- 社区、评论、分享、社交登录。
- 写作、听力、口语相关功能。

## 2. Core requirements（核心需求）

### 2.1 功能需求

### 2.1.1 用户 & 登录

- **邮箱验证码登录（必做）**
    - 用户输入邮箱，点击「发送验证码」。
    - 收到验证码后，在 App 中输入完成登录。
    - 首次登录即创建用户；再次登录则复用原账号。
- **登录状态**
    - 未登录状态只能看到登录页和简单介绍；
    - 所有核心功能（测试、订阅、阅读）需要登录后才能访问。
- **用户资料**
    - 存储内容：
        - Supabase user id。
        - email。
        - cefr_level（A1–C2）。
        - 词表相关版本号（基础词表版本 + 用户 patch 版本）。
    - 不实现：昵称、头像、个性化设置。

---

### 2.1.2 词汇测试 & 词表

- **CEFR 词汇水平测试（首次必走）**
    - 条件：用户登录后，如果 `cefr_level` 为空：
        - 引导进入词汇测试页（阻塞其他功能）。
    - 测试机制：
        - 按 CEFR 等级顺序：A1 → A2 → B1 → B2 → C1 → C2。
        - 每个等级有一组代表性单词（例如每级 20–30 个）。
        - 对每个词，询问用户「认不认识」。
        - 当某等级中 **不认识的比例 ≥ 80%**：
            - 认为用户水平 = 上一等级；
            - 若当前为 A1，则水平 = A1。
        - 若 C2 仍然认识度很高，则水平记为 C2。
    - 测试完成后：
        - 保存用户的 `cefr_level`；
        - 建立用户词表 profile（基础词表 + patch_version 初始化为 1）。
- **基础词表（Base vocab）**
    - 按 CEFR 等级划分的英文单词集合（A1–C2）。
    - 用户有效基础词表 = 所有 `cefr_level <= 用户等级` 的单词合集。
    - 有一个全局的 `base_version` 标记基础词表版本（后续更新用）。
- **用户词表 patch**
    - 用户可以对单词标记：
        - 「标记为认识」（known）。
        - 「标记为不认识」（unknown）。
    - 存储为 `lemma + status`（单词原型或统一形式）。
    - 计算有效词表：
        - 从基础词表开始；
        - 移除 status=unknown 的单词；
        - 加入 status=known 的单词（即便不在基础表中）。
- **词表版本**
    - 基础词表：`base_version`（全局）。
    - 用户 patch：`patch_version`（每个用户一份）。
        - 每次用户新增/修改 patch 时，`patch_version += 1`。
    - 翻译时记录：
        - 当前 `base_version` 与 `patch_version`。
        - 用来判断某篇文章翻译是否「过期」。
- **限制：**
    - MVP 阶段**不提供 UI 修改 CEFR 等级或重新测试**。

---

### 2.1.3 RSS 源 & 文章列表

- **内置 RSS 源**
    - 默认提供两个内置源（用户首登后可直接使用）：
        - BBC News: `http://feeds.bbci.co.uk/news/rss.xml`
        - Hacker News: `https://news.ycombinator.com/rss`
    - 用户可以不用手动输入 RSS，就能直接看到内容。
- **用户订阅管理**
    - 用户可执行操作：
        - 添加 RSS 源：输入链接 → 后端验证 RSS 可用 → 保存。
        - 查看已订阅源列表。
        - 删除已订阅的源。
    - 多对多关系：一个用户可以订阅多个 RSS，一个 RSS 源可被多个用户订阅。
- **文章列表展示**
    - 从用户订阅的所有 RSS 源中，按时间倒序列出文章：
        - 标题。
        - 来源（RSS 源名称）。
        - 发布时间。
        - 简短摘要（如有）。
    - 下拉刷新拉取最新数据。
    - 点击跳转到文章详情页。

---

### 2.1.4 文章正文 & 可读化翻译

- **正文抓取**
    - 后端根据文章 URL 抓取 HTML。
    - 提取正文 → 得到纯文本：
        - 存 raw_html。
        - 存 plain_text。
        - 可选：存 plain_sentences（分句数组，供 LLM 使用）。
- **翻译触发逻辑**
    - 用户第一次打开某篇文章时：
        - 后端查是否存在对应的 `user_article_translation` 且版本匹配：
            - 若存在且版本一致 → 直接返回简化版；
            - 若不存在或版本不一致：
                - 创建新的翻译记录（状态：pending）；
                - 同步触发翻译流程。
- **翻译行为（同步触发）**
    - 翻译步骤：
        1. 根据用户当前 `cefr_level + base_version + patch_version` 计算有效词表。
        2. 对 plain_text 分词、识别「生词」（不在有效词表中的单词）。
        3. 按句子/段落，将含生词的句子交给 LLM：
            - 提示：使用更简单的词和句式重写，尽量保留原意。
        4. 聚合 LLM 输出，生成：
            - `simplified_text`：整篇可读化正文。
            - `segments`：结构化标记，指出哪些片段被改写、对应原文是什么。
    - 性能预期：
        - 可能需要 **1–3 分钟** 才能完成；
        - MVP 不做严格时间限制。
- **翻译状态反馈**
    - 状态：`pending / ready / failed`。
    - 前端行为：
        - `ready`：直接展示简化版。
        - `pending`：
            - 显示「简化内容生成中」的状态提示；
            - 提供按钮「先看原文」。
        - `failed`：
            - 提示「暂时无法生成简化版」；
            - 展示原文阅读。
- **原文 / 简化版切换**
    - 阅读页顶部有切换开关：
        - `[简化版] / [原文]` 二选一。
    - 简化版模式：
        - 展示 `simplified_text`；
        - 按 `segments` 高亮被改写片段。
    - 原文模式：
        - 展示 `plain_text`。

---

### 2.1.5 阅读器 & 单词释义

- **阅读界面**
    - 头部：
        - 文章标题。
        - 来源（RSS 源名称）。
        - 发布时间。
    - 正文：
        - 默认显示简化版。
        - 改写过的片段有轻微视觉标记（如下划线或浅色背景）。
- **点单词释义（只支持单个单词）**
    - 用户在正文中点击一个单词：
        - 发送请求到后端，获取该单词释义。
        - 弹出释义卡片：
            - 显示：
                - 单词本身。
                - 英英释义。
                - 词性（如有）。
                - 一条英文例句。
            - 提供一个「查看中文解释」按钮：
                - 显示中文释义。
                - 显示例句中文翻译。
    - 释义内容由 LLM 生成（无额外词典接入）。
- **词汇标记（Known/Unknown）**
    - 在释义卡片中提供按钮：
        - 「标记为认识」 → 写入 `status=known`；
        - 「标记为不认识」 → 写入 `status=unknown`。
    - 每次更新：
        - 更新 `user_vocab_patches`；
        - `patch_version += 1`。
    - **MVP 行为：**
        - 当前已打开文章的简化版**不立即重算**；
        - 新的词表状态影响之后生成的文章翻译（包括这篇文章下次打开时）。
- **不支持：**
    - 拖拽选择多个单词/短语；
    - 选区释义；
    - 局部重写 patch 当前正文。

---

### 2.2 非功能性需求

- **平台**
    - Flutter + Dart；
    - MVP 输出：Android App（可在真机或模拟器运行即可）。
- **性能**
    - 翻译：
        - 整篇文章可读化可能需要 1–3 分钟；
        - MVP 不做硬性限制，但界面必须有清晰的加载状态。
    - 点词释义：
        - 目标在几秒内返回；
        - 若超时或失败，必须给出错误提示。
- **可靠性**
    - LLM 调用失败时：
        - 文章仍然可以显示原文；
        - 点词释义失败时，仅提示错误，不影响阅读。
    - RSS 抓取失败：
        - 对应源标记错误状态，展示友好文案。
- **国际化**
    - UI 文案：简体中文；
    - 阅读内容：英文；
    - 释义：默认英英，可切换显示中文。

---

### 2.3 安全 & 隐私

- 所有账号使用 Supabase Auth 管理。
- 密码不在本系统中处理（仅邮箱验证码）。
- 文章内容与用户词表存储在 Supabase Postgres，用于产品功能，不作对外分享。
- MVP 阶段不实现数据导出/删除接口，可在隐私条款中说明后续支持。

## 3. Core features（核心功能）

下面按「模块 → 用户故事 → 验收标准」列出。

### 3.1 登录 & Onboarding

- **用户故事**
    - 作为一个新用户，我希望用邮箱登录，不用记密码。
    - 作为新用户首次登录后，我希望系统帮我快速评估英语水平。
- **验收标准**
    - 输入邮箱 → 收到验证码 → 输入验证码 → 成功进入应用主界面。
    - 首次登录时，自动跳转到词汇测试页，测试完成前无法进入文章列表。
    - 测试结束后再次打开 App 不再重复测试。

---

### 3.2 RSS 订阅 & 文章列表

- **用户故事**
    - 作为用户，我希望即使不懂 RSS 也能直接看到内容（内置源）。
    - 作为进阶用户，我希望可以添加自己感兴趣的 RSS 源。
- **验收标准**
    - 首次完成测试后：
        - 若未订阅任何源，系统自动订阅 BBC News & Hacker News，并展示文章列表。
    - 用户可以：
        - 查看当前订阅源列表；
        - 添加一个新 RSS URL（成功/失败有明确反馈）；
        - 删除某个订阅源。
    - 文章列表按发布时间倒序排列。

---

### 3.3 文章阅读 & 可读化

- **用户故事**
    - 作为用户，我希望看到一篇难度合适的英文版本，而不是一堆看不懂的生词。
    - 当简化版还在生成或失败时，我仍然希望能看到原文。
- **验收标准**
    - 打开文章详情时：
        - 若已有最新版本简化内容 → 立即显示；
        - 若正在生成 → 显示「正在生成」提示；
        - 若生成失败 → 显示错误提示并提供原文阅读。
    - 简化版模式下：
        - 被改写的片段有明显标记；
        - 切换到原文模式时，展示原文全文。

---

### 3.4 点词释义 & 词表标记

- **用户故事**
    - 作为用户，我希望点击不认识的单词就能看到解释。
    - 我希望告诉系统哪些词我已经会了/不会，从而未来文章更适配。
- **验收标准**
    - 在原文/简化版中点击一个单词：
        - 弹出释义卡片，默认显示英英解释 + 例句；
        - 点「中文」后显示中文释义和例句翻译。
    - 在卡片中点击「认识」或「不认识」时：
        - 后端成功更新用户词表 patch；
        - 不会触发当前文章的立即重算（页面明显不闪、不卡）。

## 4. Core components（核心组件）

### 4.1 前端（Flutter App）

- 主要页面：
    - 登录页（邮箱 + 验证码）。
    - 词汇测试页。
    - RSS 列表页（订阅管理）。
    - 文章列表页。
    - 文章详情页（阅读器）。
- 主要职责：
    - 与 Supabase Auth 交互完成登录。
    - 调用后端 API 获取 RSS 源、文章列表、文章内容。
    - 调用后端 API 获取简化版 / 翻译状态。
    - 实现点词交互，展示释义卡片，发送词表标记请求。
    - 管理基础 UI 状态：loading / error / 空状态。

---

### 4.2 后端 API（FastAPI + SQLAlchemy + Supabase Postgres）

- 模块划分建议：
    - Auth / Profile 模块（与 Supabase Auth 集成）。
    - Vocab 模块（CEFR 测试、基础词表、patch 管理）。
    - RSS 模块（RSS 源、订阅、文章抓取）。
    - Article 模块（文章列表、正文获取）。
    - Translation 模块（可读化翻译）。
    - Glossary 模块（点词释义）。
- 主要职责：
    - 定义并实现所有 REST API 接口。
    - 使用 SQLAlchemy 操作 Postgres 数据库。
    - 管理翻译任务状态。
    - 封装 LLM 调用（统一处理 prompt 和错误）。

---

### 4.3 AI / LLM 服务

- 功能：
    - 段落级可读化翻译：
        - 输入：原句 + 生词标记 + 上下文；
        - 输出：简化句 + 标记被改写的片段。
    - 单词释义：
        - 输入：单词 + 简短上下文（可选）；
        - 输出：英英释义、词性、英文例句、中文解释、例句翻译。
- 实现：
    - MVP 可直接在后端主服务（FastAPI）中调用第三方 LLM API（兼容 OpenAI 风格）。
    - 若未来需要复杂逻辑，再考虑拆出独立服务。

### 4.4 NLP Utilities（内置于后端主服务）

- **职责**
    
    提供与「词处理」相关的基础 NLP 能力，作为后端主服务内的模块/库直接调用，包括但不限于：
    
    - 英文文本分词 / 切句；
    - 单词标准化（小写化、去标点、词形还原/lemma 等）；
    - 根据内置或外部资源对单词进行 **CEFR 等级判定/映射**（用于：
        - 词汇测试题库生成辅助；
        - 给定词表时的级别统计与检查）；
    - 对整篇文章的词频统计、未知词列表生成等辅助功能。
- **与后端主服务的关系**
    - NLP 逻辑与业务逻辑同进程运行：
        - 在请求处理流程中直接调用（函数/模块调用），不再通过 REST API/HTTP 通信；
        - 输出结构直接用于：
            - 已知/未知词判断；
            - 生词列表计算；
            - 为 LLM 准备 prompt。
- **MVP 要求**
    - 至少支持：
        - 对文章正文进行分词/分句，返回适合后续生词识别和 LLM 调用的结构；
        - 对单词做标准化（统一大小写、去掉标点）；
    - CEFR 级别判断可以先使用简单规则 / 映射（与基础词表配合），不强求复杂算法。

## 5. App / user flow（用户流程）

### 5.1 首次使用流程

1. 用户打开 App → 显示登录页。
2. 输入邮箱 → 获取验证码 → 登录成功。
3. 后端返回：无 cefr_level → 前端跳转到词汇测试页。
4. 用户完成 A1–C2 测试 → 得到 cefr_level。
5. 后端：
    - 为用户创建词表 profile；
    - 如果没有订阅源，为其自动订阅 BBC News & Hacker News。
6. 前端跳转到文章列表页，展示来自内置 RSS 源的文章。

### 5.2 日常使用流程

1. 用户打开 App → 若已有登录状态，直接进入文章列表。
2. 下拉刷新 → 向后端请求最新文章列表。
3. 点击某篇文章：
    - 前端请求文章详情和简化版。
    - 若简化版 `ready` → 展示；
    - 若 `pending` → 显示「生成中」，用户可选择先看原文；
    - 若 `failed` → 显示错误文案并展示原文。
4. 在阅读器中：
    - 切换「简化版 / 原文」；
    - 点击任意单词：
        - 弹出释义卡片；
        - 用户可查看英英 / 中文释义；
        - 可标记认识 / 不认识。
5. 阅读完成 → 返回列表或切换其他文章。

### 5.3 异常 & 边缘流程

- RSS URL 无效：
    - 后端校验失败 → 返回错误；
    - 前端在添加源时提示「RSS 无法解析」。
- 文章抓取失败：
    - 后端返回错误标记；
    - 前端在详情页提示「暂时无法获取正文」，可选择打开原链接（可选）。
- LLM 调用超时/失败：
    - 翻译失败 → `status=failed`；
    - 点词释义失败 → 卡片内显示「释义暂时不可用」。

### 6. Techstack（技术栈）

- **前端**
    - Flutter + Dart。
    - UI：以手写基础组件为主，不强制引入复杂 UI 库，以「可用」为原则。
- **后端主服务**
    - FastAPI + Python。
    - SQLAlchemy 作为 ORM。
    - Supabase Postgres 作为数据库存储：
        - 用户信息；
        - 词汇 profile 与 patch；
        - RSS 源与文章；
        - 翻译结果等。
    - Supabase Auth：
        - 邮箱验证码登录（magic link/OTP）。
- **NLP Utilities**
    - 作为后端主服务内置模块：
        - 负责分词、切句、词形还原、词级别判断等底层 NLP 操作；
        - 通过函数/模块调用直接使用，不走 REST API。
- **AI / LLM**
    - 支持 OpenAI 风格的 LLM HTTP API。
    - 用途：
        - 文章可读化简化（基于生词列表重写句子）；
        - 单词释义生成（英英 + 中文解释与例句翻译）。
- 调用链：
    - 后端主服务根据用户词表 + NLP Utilities 输出的分词/生词信息，构造 prompt；
    - 再调用 LLM 生成简化文本与释义。
- **部署（MVP 可简化）**
    - 后端主服务（FastAPI）部署在任意支持 Python 的平台（例如 Railway / Render / VPS 等）。
    - 数据库由 Supabase 托管 Postgres。
    - 不强制做完整 CI/CD，手动部署即可。
